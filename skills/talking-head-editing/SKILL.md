# 🎬 Talking-head editing

Produce a coherent spoken narrative with complete words, natural timing and deliberate visual transitions. A clean transcript or successful render does not establish a good edit.

Before editing, read [failure mechanisms and review criteria](references/review-method.md). For choosing tools or evaluating claims about automated editing, read [evidence and limits](references/evidence.md). Keep project-specific paths, source/output versions and mastering settings in a separate project handoff, not in this reusable skill.

## 🧭 Work sequence

Perform these stages in order, revisiting selection when boundary repair cannot preserve a complete sentence:

1. **Establish the project contract.** Identify the actual source, current reviewed export and edit manifest. Check local instructions, privacy restrictions, audio source, desired framing and future assembly plans. Preserve originals. Inventory local tools, model cache and available disk before rendering. Do not assume cloud ASR or upload permission.
2. **Understand the whole narrative.** Transcribe with word timing, then read the complete recording. Identify repeated attempts, abandoned starts, off-camera instructions and intentional emphasis. Select the most coherent complete take in context; neither the last nor the longest attempt is automatically best. Preserve reasons and source ranges.
3. **Place audiovisual boundaries.** Refine rough transcript times using short overlapping recognition windows, speech/waveform evidence and moving image context. Check quiet phonemes and discarded mouth preparation. Leave enough release and lead-in for the chosen words; retain purposeful pauses. Use the detailed reference to evaluate every dimension, not only the suspected defect.
4. **Build a traceable edit.** Record source identity, source start/end, intended wording, framing, reasons, output times and review status. Use frame-aligned ranges where appropriate; keep audio and video on the same source timeline. Preserve compatible PCM or lossless audio intermediates for later mastering. Collect corrections before a whole-programme export; short internal previews are appropriate.
5. **Review the rendered result independently.** Re-transcribe the actual output, compare intended speech, inspect every join and suspicious retained passage, and use an available listening-capable path for audible review. Recheck complete narrative coverage, not only joins. Correct evidenced defects and repeat affected checks plus whole-programme checks that the changes invalidate.
6. **Verify delivery.** Check full decode, expected frame count/duration, AV alignment, measured loudness/true peak and compatibility. Report the artifact, corrections, verified coverage and unresolved limits. Never equate ASR, signal measurements or still images with having listened/watched continuously. Do not ask the user to identify defects that can be investigated independently.

## 🎚️ Multi-clip consistency

Maintain one project contract for dimensions, frame rate, colour handling, audio sample rate/channels and loudness/peak targets. Do not blindly copy settings if source colour or orientation differs. Deliver pieces separately when requested, retaining source edit decisions and high-quality audio for final assembly. When joining later, review the inter-piece transitions and measure/master the assembled programme as a whole.

An approximately −14 LUFS integrated target with conservative true-peak headroom can be a project choice, not a universal quality law or guaranteed platform requirement. Verify current platform guidance if making a platform claim. Integrated loudness alone does not prevent locally quiet phrases or mask music. Add music only when requested or accepted; balance against intelligibility and verify actual playback, not only meter values.

## 🛑 Completion boundary

Continue until detected defects are corrected and the declared checks pass. If tools cannot establish a required perceptual property, record that specific missing capability and pursue a suitable authorized method. Do not repeatedly change framing as a substitute for identifying the fault, indefinitely tune against the same fallible transcript, or claim a guaranteed flawless automatic result. Preserve unresolved items in the project handoff so compaction cannot silently turn them into completed checks.
